WHERE, GROUP BY, HAVING — which one, when?

Change the query, then click each stage to watch your rows flow through Snowflake.

Golden rule: a filter on a single row goes in WHERE. A filter on a total (SUM, COUNT, AVG) goes in HAVING.

3. The query template
SELECT region, SUM(amount) AS total -- 5 pick columns
FROM orders -- 1 read table
WHERE status <> 'CANCELLED' -- 2 filter rows
GROUP BY region -- 3 make groups
HAVING SUM(amount) > 1000 -- 4 filter groups
ORDER BY total DESC; -- 6 sort

This is the order Snowflake actually runs the clauses in — not the order you write them.
single row → WHERE group total → HAVING

WHERE

Filters individual rows before any grouping or math happens.

WHERE region = 'West' AND amount > 200

GROUP BY

Squashes rows that share the same value into one summary row.

GROUP BY region

HAVING

Filters entire groups using aggregates like SUM, COUNT, or AVG.

HAVING SUM(amount) > 1000

ORDER BY

Sorts the finished rows at the very end. Can use SELECT aliases.

ORDER BY total_sales DESC

QUALIFY (Snowflake)

Filters results of window functions without needing a subquery.

QUALIFY ROW_NUMBER() OVER (PARTITION BY region ORDER BY amount DESC) = 1

GROUP BY ALL (Snowflake)

Automatically groups by every non-aggregated column in your SELECT list.

SELECT region, product, SUM(amount) FROM orders GROUP BY ALL

1. Putting SUM() inside WHERE Click to inspect ↓
SELECT region, SUM(amount) FROM orders WHERE SUM(amount) > 1000 GROUP BY region;
Snowflake error: Invalid aggregate function in where clause

Why: WHERE runs before GROUP BY, so group totals do not exist yet.

SELECT region, SUM(amount) FROM orders GROUP BY region HAVING SUM(amount) > 1000;
2. Missing a SELECT column in GROUP BY Click to inspect ↓
SELECT region, product, SUM(amount) FROM orders GROUP BY region;
Snowflake error: 'PRODUCT' is not a valid group by expression

Why: Every unaggregated column in SELECT must also be listed in GROUP BY (or use Snowflake's GROUP BY ALL).

SELECT region, product, SUM(amount) FROM orders GROUP BY region, product; -- or GROUP BY ALL
3. Filtering a normal column in HAVING Click to inspect ↓
SELECT region, SUM(amount) FROM orders GROUP BY region HAVING region = 'West';
Result: Works, but it is the slow way.

Why: Snowflake groups every region first and throws away the others later. Filter single-row values early in WHERE.

SELECT region, SUM(amount) FROM orders WHERE region = 'West' GROUP BY region;
4. Filtering a window function in WHERE Click to inspect ↓
SELECT *, ROW_NUMBER() OVER (PARTITION BY region ORDER BY amount DESC) AS rn FROM orders WHERE rn = 1;
Snowflake error: Window function not allowed in WHERE

Why: Window functions run after WHERE and HAVING. In Snowflake, use QUALIFY.

SELECT *, ROW_NUMBER() OVER (PARTITION BY region ORDER BY amount DESC) AS rn FROM orders QUALIFY rn = 1;
